# Lore Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans (Native, or its Native with reviews variant) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Docusaurus docs site for Lore in `site/`, deployed to GitHub Pages on `cli-v*` tags, with a Guide, a Reference (format and CLI), the spec split by section, and coverage tests that tie the Reference to the CLI and the schemas.

**Architecture:** `site/` is a standalone Docusaurus 3 project outside the bun workspace. A bun generator (`site/scripts/`) writes the Specification pages (spec sections, the error registry, schemas) into a gitignored `site/docs/spec/` before every build. Hand-written pages live in `site/docs/`. Root `bun test` covers the generator and checks the CLI pages against the CLI's own help text and flag lists.

**Tech Stack:** Docusaurus 3 (`@docusaurus/core`, `@docusaurus/preset-classic`, latest 3.x), `@easyops-cn/docusaurus-search-local`, `docusaurus-plugin-llms` (for `llms.txt` and Markdown copies), `github-slugger` (root devDependency), bun 1.4.3, GitHub Actions Pages (`actions/upload-pages-artifact`, `actions/deploy-pages`).

**Spec:** `docs/superpowers/specs/2026-11-19-lore-docs-site-design.md`

## Global Constraints

- Site URL `https://m4ttstack.github.io`, `baseUrl: "/lore/"`, docs at the site root (`routeBasePath: "/"`).
- `onBrokenLinks: "throw"`, `onBrokenAnchors: "throw"`, `markdown.hooks.onBrokenMarkdownLinks: "throw"`.
- `markdown.format: "detect"`: `.md` files are CommonMark (no MDX), so spec text with raw `<rule>` tags renders safely. Write hand-written pages as `.md`; use `.mdx` only where a page needs a component.
- `site/` is not a bun workspace member; it has its own `package.json` and `bun.lock`.
- Nothing generated is committed: `site/docs/spec/`, `site/build/`, `site/.docusaurus/` are gitignored.
- Writing style is the design doc's "Writing style" section, modelled on Vale, ESLint, ast-grep and Semgrep (its "Models" section). In short: guides say "you", reference pages use the third person; sentences of about 10 to 25 words; paragraphs of one to three sentences; an example follows the sentence that introduces it and is followed by one sentence on what it shows; tool output in examples comes from real runs; callouts are rare (tip, note, warning), and version gates read "Requires lore X.Y.Z or later."; guide and concept pages end with "Next steps" (two to four links, one sentence each); no em dashes (`—`) or en dashes (`–`) anywhere.
- Concept pages explain in plain words and link to spec sections; they never paste normative spec text.
- Every behavior claim on a page is checked against the source (`packages/cli/src/`, `packages/parser/src/`, `spec/SPEC.md`) before it is written.
- CI pins bun 1.4.3.
- Edits to code blocks in the root `README.md` change fixtures: run `bun scripts/fixtures.ts` and commit any `test/fixtures` change.

## Review Focus

1. A `##` line inside a fenced block (six-backtick examples, the seven-backtick fence around the demo example in "Conformance examples", and `## Money ...` headings inside example inputs) must never start a page. Pinned in Task 2.
2. A spec link to a heading whose slug GitHub dedupes (`### Refunds` appears twice, so the second is `refunds-1`) must land on the page and heading GitHub would land on. Pinned in Task 2.
3. `spec/errors.json` and the spec's Errors and warnings table drifting apart must fail generation, naming the first mismatched code. Pinned in Task 3.
4. Section titles with punctuation (`.loreconfig`, `For agents (non-normative)`) must give stable, valid page ids (`loreconfig`, `for-agents-non-normative`). Pinned in Task 2.
5. A flag added to `packages/cli/src/args.ts` but left out of the `--help` text must still be caught by the coverage test. Pinned in Task 5.

### Task 2: Split the spec into pages

**Files:**
- Create: `site/scripts/spec.ts`
- Test: `tests/docs-site/spec.test.ts`
- Modify: `tsconfig.json` (add `"site/scripts"` to `include`), root `package.json` (add `github-slugger` to `devDependencies`)

**Interfaces:**
- Consumes: `extractExamples(markdown: string): Example[]` from `tools/check/extract.ts` (gives each example's `number`, `kind` and `line`).
- Produces:

```ts
export interface SpecPage { id: string; title: string; position: number; body: string }
export interface SplitOptions { ref: string } // git ref for GitHub links, e.g. "cli-v0.7.0" or "main"
export function splitSpec(markdown: string, options: SplitOptions): SpecPage[]
```

`id` is the github-slugger slug of the `##` title; `body` is the page's Markdown with front matter (`title`, `sidebar_position`, `id`) and every rewrite below applied.

Rules `splitSpec` applies:
- Pages start at `##` lines outside fenced blocks. Fence tracking matches `extractExamples`: a fence closes only on a line of the same character, at least as long as the opener.
- The text before the first `##` (the `# ` title line) is dropped.
- Every heading (`##` to `######`) outside fences gets an explicit id `{#slug}`, where the slug is computed by one `GithubSlugger` over the whole document in order. That keeps every anchor GitHub gives `SPEC.md`.
- `](#anchor)` links are rewritten to `](./<page-id>.md#anchor)` when the anchor is on another page, left as is when it is on the same page, and throw `Error("spec link #<anchor> matches no heading")` when no heading has it.
- `](AGENT.md)` → `](./for-agents-non-normative.md)`; `](errors.json)` → `](./errors-and-warnings.md)`; `](schemas/)` → `](./schemas/index.md)`; `](schemas/<name>.schema.json)` → `](./schemas/<name>.md)`; `](../LICENSE)` and `](../LICENSE-CC-BY-4.0)` → `https://github.com/m4ttstack/lore/blob/<ref>/LICENSE...`. Absolute `http(s)` links are left alone. Any other relative link throws.
- Each conformance example's opening line `` ``````example <kind> `` becomes `` ``````text title="Example <number> (<kind>)" ``, using the number `extractExamples` gives the example at that line. Its closing line stays.

import { describe, expect, test } from "bun:test";
import { readFileSync } from "node:fs";
import { splitSpec } from "../../site/scripts/spec";

const spec = readFileSync("spec/SPEC.md", "utf8");
const pages = splitSpec(spec, { ref: "main" });

describe("splitSpec", () => {
  test("one page per top-level section, in order", () => {
    expect(pages.map((p) => p.title)).toEqual([

      "Document model", "Errors and warnings", "For agents (non-normative)", "Adopting Lore (non-normative)",
    ]);
    expect(pages.map((p) => p.position)).toEqual(pages.map((_, i) => i + 1));
  });
  test("ids from punctuated titles", () => {
    expect(pages.find((p) => p.title === ".loreconfig")!.id).toBe("loreconfig");
    expect(pages.find((p) => p.title === "For agents (non-normative)")!.id).toBe("for-agents-non-normative");
  });
  test("headings inside fences never split", () => {
    const md = "# T\n\n## A\n\n```````\n``````example parse\n=== a.lore\n## Not a page\n``````\n```````\n\n## B\n";
    expect(splitSpec(md, { ref: "main" }).map((p) => p.title)).toEqual(["A", "B"]);
  });
  test("cross-page anchors point at the right page", () => {
    const md = "# T\n\n## A\n\nSee [b](#b-two).\n\n## B\n\n### B two\n";
    expect(splitSpec(md, { ref: "main" })[0]!.body).toContain("](./b.md#b-two)");

    const [a, b] = splitSpec(md, { ref: "main" });

    expect(b!.body).toContain("### Refunds {#refunds-1}");
    expect(b!.body).toContain("](#refunds-1)");
  });
  test("an unknown anchor throws", () => {
    expect(() => splitSpec("# T\n\n## A\n\n[x](#nope)\n", { ref: "main" })).toThrow("spec link #nope matches no heading");
  });
  test("examples get numbered titles", () => {
    const all = pages.map((p) => p.body).join("\n");
    expect(all).toContain('``````text title="Example 1 (');
    expect(all).not.toMatch(/^``````example /m);
  });
  test("file links are rewritten", () => {
    const all = pages.map((p) => p.body).join("\n");
    expect(all).toContain("](./for-agents-non-normative.md)");
    expect(all).toContain("](./schemas/audit.md)");
    expect(all).toContain("https://github.com/m4ttstack/lore/blob/main/LICENSE");
  });

### Task 3: Error registry and schema pages

```ts
export interface RegistryEntry { name: string; kind: "error" | "warning"; description: string }
// Replaces the Name | Kind | Description table in the Errors and warnings page with one `### <name> {#<name>}`
// heading per code (errors first, then warnings, each in errors.json order), each followed by
// "**Kind:** <kind>" and the description. Throws if the table and the registry differ.
export function errorsPage(page: SpecPage, registry: RegistryEntry[]): SpecPage
export interface SchemaPage { id: string; title: string; body: string } // id: file name without .schema.json
export function schemaPages(schemas: { file: string; json: string }[]): SchemaPage[] // plus one with id "index" listing them
```

The Errors and warnings page sets `toc_max_heading_level: 2` in its front matter so the table of contents does not list every code. Each schema page shows the schema's `title` as its heading, its `description`, and the schema in a `json` code block. The index page links each schema page by title.
